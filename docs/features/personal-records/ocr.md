# v0.10 本机 OCR 与资料收录

## 怎么用

首页「资料」里粘贴截图或选择 PNG/JPEG/WebP/PDF，点「保存并整理」。原件先落盘，worker 再执行本地文字识别、分段模型整理和检索索引。飞书收件配置完成后，收到的图片和PDF也使用这条管线，无需单独申请OCR服务。

已保存但尚未识别的旧图片，在详情点「重试处理」。长扫描件每轮最多识别10个缺文字页；有剩余时显示「继续识别与整理」。空白页与识别失败页均明确显示，不将其算作完整读取。已识别页缓存复用，不反复占用识别时间。

「原文片段与页码」可核对转写稿、物理页码与OCR标记，并下载原件。发现错字时用现有纠正批注，写清页码和正确内容；后续回答会同时获得当前纠正。批注不会覆盖原图或直接改写OCR稿，也不代表所有原文主张已重新验证。

## 实现

- PDF.js优先读取文字层，少于15字的页用PDFKit渲染后交给Apple Vision；有足够文字层的页面不会再次OCR，因此混合页中的独立图表文字仍可能遗漏。
- PNG/JPEG/WebP按文件内容校正MIME，ImageIO缩略图应用方向信息；Vision中英文识别，关闭自动语言纠词以减少对数字和专名的擅自改写。
- 独立本地进程，无模型Key、无资料上传。源码使用Objective-C直接调用系统框架，由macOS Command Line Tools编译到忽略的`data/runtime`；不依赖Swift模块缓存，也不提交二进制。
- 单文件15MB，图片最长边4000像素，PDF渲染最长边3000像素，每批最多10页、90秒识别、4MB进程输出，每页最多5万字；超出时明确标为不完整。超时保留已经返回的完整页；删除/修改使旧任务停止，取消信号触发后不写回解析结果。这里是资源约束，非操作系统沙箱。
- OCR本身不消耗Kimi额度；后续提取、问答仍使用现有模型、账本和预算，不上调月度限额。
- 共享资产只追加新页片段，保留旧片段ID和引用；相关资料的全文索引与向量待更新状态一起刷新。旧模型回答仍代表生成时材料范围，不自动补写为已通读新页。
- 解析信息记录引擎、页面、字符数及识别置信提示。置信值不是事实正确率；逐字引用验证也只证明匹配转写稿。
- macOS可用；Linux/Windows保留原件并说明OCR不可用，尚未接入跨平台替代引擎。当前机器已验证，其他系统版本未承诺兼容。

## 边界

不做K线走势、图片语义或复杂表格关系理解；没有文字的图不会被编造说明。模型仍每轮最多整理前12片段；剩余OCR文字能全文搜索，但不假装已经模型提取。语音转写、Office解析与飞书富文本收件尚未接入，本轮不扩大到这些格式。

验证用明确标注的合成截图和PDF，不收录个人投资记录，不发送飞书测试消息。自动测试的模型提取使用明确测试替身，OCR真实调用系统Vision；真实模型结果单独说明，不能以程序替身宣称已验收全部AI效果。

官方接口：[Vision文字识别](https://developer.apple.com/documentation/vision/recognizing-text-in-images)、[PDF页缩略图](https://developer.apple.com/documentation/pdfkit/pdfpage/thumbnail(of:for:))、[ImageIO缩略图](https://developer.apple.com/documentation/imageio/cgimagesourcecreatethumbnailatindex(_:_:_:))。
