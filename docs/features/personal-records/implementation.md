# v0.8.0 实现与使用边界

## 原有能力与实际增量

保留Next.js/React、本机3210、SQLite、runs/worker、模型调用与预算。资料模块复用`agentCall`（原配置的Kimi/Harness），来源提取输出限2048 Token；每份资料每轮最多12个3500字片段，逐段验证引用。不是全文一口气塞入模型。复用中文分词/双字关键词、E5本地向量与RRF思想，未安装向量模型时仍有关键词检索；本地向量仅覆盖每条索引的前1800字（模型还会按512 Token截断），不能宣称全文语义索引。全文关键词索引覆盖已解析全部片段。对比最多3份、每份召回6个相关片段。

`server/library/`：db数据结构，assets内容哈希存储，web受限网页获取，parse隔离PDF解析，service受控CRUD/索引/纠正/删除，processor分段提取与关联，answers带来源问答，conversation明确自然语言操作。`server/feishu/`：应用私密配置、长连接runtime、receiver消息鉴权/去重/回复。`app/api/library`、`app/library-panel.tsx`新增轻量入口。原通知outbox扩展`library_feishu`渠道，不使用群Webhook接收消息。

## 数据与迁移

启动模块时使用CREATE TABLE IF NOT EXISTS增量建表，不重建旧库。新增`library_assets/entries/ingestions/submissions/chunks/extractions/claims/annotations/versions/links/jobs/index/fts/audit/task_sources/run_sources/answers`和`feishu_inbox/replies/runtime`。`library_jobs.stage`采用存在性检查后ALTER追加，用于区分解析重试与可能已计费的模型中断。

原始文件保存在`data/library-assets/<sha256>`，0600权限；目录0700。不同收录事件有独立记录与批注，同哈希复用文件、解析与相同模板/模型的提取结果。重复消息事件不重复收录；标题和URL不是内容去重键，同链接下次获取新正文可成为不同资产。PDF物理页码从1开始。

记录和来源观点不会写入旧个人持仓/规则记忆表。模型无用户ID或任意SQL工具。单用户所有权由本机接口或飞书授权映射到固定local，不接受请求体owner。用户立场来自明确原话的保守规则或手动声明；局部立场保存在具体批注及可选主张目标上，不升级成整篇认同或长期偏好。模糊表达保留原话，结构化状态未知。

## 状态与恢复

原始资产、解析、提取、关联、索引分别保存状态；飞书发送状态在原outbox。无正文的链接只显示链接已保存。v0.10加入macOS本地OCR：图片自动识别，PDF优先读取文字层、缺文字页分批识别，原件不变。见[OCR说明](ocr.md)。PDF最多100页、50万提取字符，单子进程256MB堆、30秒；网页最大5MB，最多3次跳转，每跳公网HTTPS校验并将DNS解析结果绑定到连接，禁止私网/回环/保留地址。HTML脚本不执行，仅以纯文本展示。

未明确意图的附件进入待确认；资料收集模式由用户开启。仅分析进入session，不加入长期索引，日志/原件保留到用户删除，并非自动彻底销毁。待确认按文件名在对应列表可见，确认收藏后加入关键词检索。

原runs负责排队、互斥claim与心跳；资料作业按记录版本去重，解析中断最多2次延迟重试。进入模型阶段后不自动重复计费，需手动重试。部分模型结果保存已通过引用校验的部分；缺口显示数量。后台休眠不能执行。飞书事件先持久化再处理，排队任务跨重启保留；中断的修改操作不盲目重做，发送明确失败回执。SDK连接错误限频重连。

## 纠正、关联、删除

纠正生成新版本，原批注成为历史；当前索引撤销旧立场，相关回答、队列与关系失效。普通笔记纠正后不再从旧正文重新生成当前个人主张；原件和历史仍可查看。收藏作者的材料保持原作者文本，绝不把纠正覆盖到原文。

关联仅依据已引用的相同对象或同一原始资产，保存双侧证据和期间/口径差异；默认系统建议，不声明支持/证伪。拒绝记录保留以避免下一轮立即恢复。转载正文完全相同可识别同资产；不同文字转载目前不保证识别，不能声称跨站独立来源已自动核验。

删除记录需当前版本确认，清理本机记录、批注、历史、提取、关系、索引/向量、派生问答、相关主聊天回答及待办，取消在途旧作业。无其他记录引用时删除原资产及其解析缓存；共享资产不会误删。删除批注会清理含它的历史版本和派生回答（不等于删除整份原始资料）。审计只留ID、动作和范围，不留被删正文。已发飞书消息、模型服务保留内容和独立备份不能承诺远端彻底删除。

## 本机用法

`npm ci` → `npm run build` → `npm start`，仍为http://127.0.0.1:3210。首页右上“资料”：输入想法/资料、可选链接或附件和关注点；选择收录、记录想法、仅分析或待确认。无需填标签/风险偏好。详情可下载原件、看页码片段、批注、纠正、看版本、移除关联、删除。多选最多3份后提问，或用疑问、代码、时间搜索。

原对话支持明确指令：“记录想法：…”“收藏资料：https://…”“找回资料：需求改善证据不足”；回复该记录结果可纠正/追问/对比。多候选修改需指定编号，不靠最近一条猜对象。自然语言网关有限，不宣称任意复杂话语已可靠映射工具。

后续委托只写入原tasks表的`library_followup`草稿，与资料版本绑定；本版不直接启用产业逻辑监控。原跟进页如实显示尚未执行，纠正时暂停、删除时清理。

## 飞书配置与交互

当前只有群Webhook，不能接收用户文件。新增适配需要**飞书企业自建应用**（在个人当前飞书组织中是否可创建/发布，取决于账号权限）：启用机器人、配置可用范围，订阅`im.message.receive_v1`并选择长连接。无需公网回调地址。

最小权限按使用入口申请：`im:message.p2p_msg:readonly`（单聊接收）；群入口另需`im:message.group_at_msg:readonly`并@机器人；`im:message:send_as_bot`（回复）；`im:message:readonly`（读取消息及下载消息中的图片／文件资源，不能用 `im:resource` 代替）。发布应用版本后才按实际可用范围生效。具体权限以开放平台审批结果为准。

在“资料 → 飞书收件连接”填App ID、App Secret、授权用户open_id，必要时限定chat_id；手动启用。默认未启用，默认附件不自动收藏。`data/feishu-app-credentials.json`仅本机0600保存，不进导出/Git/日志；未授权用户直接忽略，不向其暴露资料或身份信息。

- 给应用机器人发“这篇存一下”加链接，或上传PDF。未开启收集模式时，附件先待确认；回复原消息/记录卡“帮我收一下，我想核实需求改善证据”即可确认并保存批注。
- 回复记录卡“补充：…”“纠正：…”；不使用群内任意最近消息猜目标。
- 发“找回：需求改善证据不足的报告”；多结果给编号，再回复或指定编号。
- 回复“原文”返回有定位的前3个片段，并明确不是全文；完整原附件仍在原发送消息，本机可下载。
- 回复“对比 <记录编号1> <记录编号2> …”取得有引用回答。
- 回复“删除记录”，再按返回的编号和版本确认；不直接执行有歧义删除。

卡片是简短静态交互卡，使用原消息回复文本操作；首版没有点击式回调按钮，不额外申请卡片回调权限。文件/图片/文字与富文本post（文字说明＋附件）已实现；语音、文件夹、合并转发等显示未接入，不假装收录全部附件。同一批多个文件可在本机一次提交；飞书逐条消息分别保存收录关系。

### v0.10.1 复合消息

飞书客户端可将说明和PDF封装为post，附件位于顶层files数组，而非独立file消息。本版优先读取content_v2、兼容content和本地化结构，收取files及正文img/file节点，按资源Key去重；附带说明直接作为每份材料的用户说明保留，不另生成孤立文字记录。最多5个附件，先全部下载再收录，并再次检查授权；不支持的内容明确提示整条未收录。

已处理的旧消息仍保持事件去重，不会因升级自动重放。若曾收到“格式未接入”，请将原来的说明＋文件重新发送一次。

### v0.10.2 整理与续作

source-extraction/2.0将单片段分为连续原文证据块，模型返回E编号，程序回填真正原文与chunkId；未知编号或系统推断冒充作者内容被逐项拒绝，其余保留。精确引用检查继续执行，不用模糊相似度放过错误数字。编号归属验证不等于语义蕴含或外部事实核验。

按资产、模板版本、模型、片段缓存；所有完成片段先恢复，再每轮最多调用12个未完成片段。仍有问题时保留合格内容和诊断。重试保留当前有效主张、使旧派生回答失效，并在新版本续作；同时点击或回复多次复用同一在途任务。飞书回复唯一对应资料卡“重试整理／继续整理／重新整理”，无需重传附件。
