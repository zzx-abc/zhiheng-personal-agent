# 实施计划

现状（2026-11-13代码盘点）：Next.js/React/TypeScript，SQLite，现有runs/worker，Kimi/Harness用量控制，本地E5混合检索，飞书群Webhook仅出站。保留现有聊天与雷达，不把资料正文放入个人原话/持仓卡片。

1. 扩展SQLite：资产、收录事件、资料版本、片段、带引用的主张、批注、关系、作业映射与回执。原始资产按内容哈希复用，收录行为单独保存。
2. 文字/PDF/网页先持久化后处理；PDF按物理页提取，网页限制公网HTTPS及逐跳地址校验。使用受限子进程隔离PDF解析；结构化提取复用真实Kimi调用与预算。超限保留未处理范围。
3. 复用runs/worker执行版本化作业。关键词/结构过滤即时可用，本地E5可用时补充语义检索。引用须匹配已提供片段，外部观点不能写成用户事实。
4. 受控服务提供搜索、读证据、批注、纠正、对比、删除、任务草稿。界面加入轻量资料入口。明确收录与仅分析/待确认的区别。
5. 飞书自建应用长连接接收，授权用户和会话校验，事件去重、附件资源下载、回复关系与持久回执。缺少凭据时完成适配测试，不宣称真实连通。
6. 隔离测试、安全与删除测试、浏览器闭环，文档、版本、Git发布。真实模型测试有限执行，保留账本，不调整额度；未经授权不发真实飞书测试消息。

决策：不新增向量数据库/消息中间件/Agent框架；资产处理与用户立场分开；自动关联仅为可撤销建议；当前立场通过最新版本与批注明确来源回答。没有明确授权不生成长期用户规则，不启用监控。
