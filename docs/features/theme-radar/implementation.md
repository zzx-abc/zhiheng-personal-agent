# v0.9.0 多主题雷达实现

## 旧问题与增量

代码检查确认旧配置只接受十个中证行业ID、固定数量等距抽样，不能加入指定股票；行情质量同时依赖价格、量、历史，缺一个字段容易隐藏已知事实；一组分类缺失会阻止整个批次；用户结果主要是指标/日志。旧3/5日指标包含当前盘中收益，不能直接称为完整3/5交易日。

新增指定主题模式，保留市场发现的旧行业抽样模式。共用原SQLite、后台worker、行情批量请求/缓存、交易日历、runs与飞书outbox。没有重写主Agent或引入额外模型调用。新算法是观察规则，并未回测盈利能力。

## 模块与数据

- `theme-types.ts`：可校验的主题、成员、业务来源、指标与结果模型。
- `theme-seeds.json`：三个公开示例配置；私人价格参数不进入源码。每个业务映射有来源与核验日期；官网、披露、系统定位分开。
- `themes.ts`：`observation_themes`版本库。任务config只引用主题ID和固定版本；更新主题不静默改变现有任务。采用新版本后重新建基线。
- `provider.ts`：主题模式不再调用行业抽样；合并证券代码，单批次每证券一次日K采集、共享报价；所有核心对象即使缺失仍写入结果。行情名称与代码不匹配时拒用报价。
- `theme-engine.ts`：完整日区间、相对强弱、动态高点、个人价格条件、分层状态、跨主题比较和文本模板。`observation_theme_states`隔离各任务状态。
- `service.ts`：原调度与事务检查接入主题结果；原`frames/checks/signals`保留配置快照、条件数值、版本及证据。回放只读当时帧与配置，不拉新行情、不推送、不计算收益。
- `app/theme-report.tsx`：主题对比、十只核心股票、辅助股、业务依据/条件/缺口；不是把日志改写为研究结论。
- `app/theme-config.tsx`：主题选择与高级JSON版本编辑。新主题通过数据配置复用引擎，首版尚无图形化证券选择器或自动核验任意新增业务映射。

## 指标口径

所有任务使用Asia/Shanghai及已有2026交易所休市日历；未知年份停止自动调度，须维护下一年度官方日历。

- 3/5日：固定在此前完整交易日的4/6个收盘点上，`(末收盘/初收盘-1)*100`。保守排除抓取当日，不能用当日未完整K线补齐。缺日期不能缩短窗口参与排名。
- 相对：个股收益减沪深300同窗口收益，单位百分点。主题精选公司等权；缺样本不参与主题排序，也不因为缺失负指标而得分更高。盘中相对单列，报价相差超过5分钟不比较。
- 辅助行业基准：单独计算个股对ETF3/5日差，ETF有溢价和跟踪误差。无数据则标缺失，不把共同宽基与行业基准混合成分数。
- 近20日高点：此前完整交易日最高价，不含当日。用同批次前复权高点/前复权昨收×报价昨收折算到当期原价，保存本轮值、期间、公式和基准；未来复权变化不能改写已存信号。
- 历史个人价格线：保存来源日期、原价口径、适用截止、核验截止及依据。未核验、无有效期或过期只展示，不触发；不生成目标价/支撑位。
- 量能：盘中没有历史同时间累计量，明确无法验证；不拿半天量比历史全天均量。最终日量必须有最终标志、同口径单位和20个完整日，才计算当天/前20日均量。目前腾讯适配不满足，所以不会声称放量或正式收盘确认。

三层输出：个股条件、细分精选样本（单股明确不能验证广度）、主题间同窗等权相对比较。跨环节共享一家公司不能当多份独立确认；全局股票数、事件按证券去重。上涨最多不能自动称“新主线”，也不推断资金从A流到B。

## 状态与通知

每个任务、配置、主题、对象和规则有独立状态。首次有效观察建立静默基线；后续需至少2个不同时间快照且间隔不小于检查频率。重复快照不累计；未知条件保持先前状态但当前报告明确缺口，不把缺失转为风险/增强。持续满足静默，连续进入增强、条件失效/风险及确认阶段升级才产生事件。新配置/离线恢复重建基线。

正式收盘与次交易日持续确认只有数据源提供真实最终标志才可升级；重复盘中检查不能替代两个收盘日。实际腾讯源未提供这些标志。事件保存版本与阶段，outbox仍执行启用、配置epoch、过期与回执约束；同股同方向多规则/多主题事件在本轮合并，单批次一条消息。没有新事件时不发全量体检。

主题任务每30分钟固定交易时段槽：09:30、10:00、10:30、11:00、13:00、13:30、14:00、14:30。午休、周末、节假日不跑；休眠错过的时点不补发一串旧提醒。本机进程存活且Mac清醒才运行，关闭浏览器不影响worker。没有额外收盘调度，避免把未确认快照叫作正式收盘。

## 操作

首页持续观察 → 选择任务 → 当前完整体检；每只核心股都有价格时间、历史/盘中分列、条件、下一步与来源。现在检查一次可手动刷新，包括非交易时段的只读事实；非有效时间不产生价格触发。

调整配置 → 指定主题观察 → 选择主题版本 → 保存。高级“维护主题、股票与规则”可以另存新主题或追加版本；需提供可靠业务依据，不能将模型猜测设成已核验事实。保存主题后要明确采用版本并保存任务才生效；否则原任务继续固定旧版本。

`npm run radar:themes -- --live`在隔离临时库进行真实行情只读验收，输出到忽略的artifacts；不使用模型、不读取私密通知连接、不发外部消息。生产启用通过既有任务API，不靠对话承诺。
