# 私聊研究事项 · 阶段 0 基线

起点为 89d4434。将任务书主问题作为本人私聊文本送入隔离的真实 receiveMessage / processFeishu，传入计数模型替身，未发送消息。实际调用模型 0 次、创建资料 1 条，首句为“已收录”。旧意图匹配把“之前保存的”认作本次收藏指令。

- Web 的 engine/intake 在检索后再次理解意图；research.ts 会把公告检索结果交给模型，由模型决定停止或再查一次（最多两次）。行情计划交给确定性行情工具。分析、质疑和 Leader 审议不具备任意工具执行权。
- 飞书 unified-router 已能按 E 号固定执行“定位事件—检索资料—回答”，R 号原只支持检查事实和比较。普通私聊 chat 只用最近同范围对话，不读资料。三个路径没有共享的结果驱动的跨模块决策。
- 身份、场景、消息幂等和受众由 Feishu scope、inbox、outbox 和 generation 管理。SQLite 保存原始资产、批注/版本、雷达快照/事件和运行记录。资料有 OCR、检索、版本失效；雷达有真实历史检查，不保证正式收盘数据。
- 已有 Node worker、分槽队列、SQLite 事件和项目内任务方法。已有 DSH/SDK 均锁定 0.2.2-rc.1；适配器限制为模型调用，结构化 JSON 可交给程序选工具。继续使用该接口与现有月预算。各模块已有局部错误/状态，尚无统一研究工具结果。无需新增运行时、通用技能系统或事件总线。

首轮范围为授权私聊的资料、历史雷达和证据补查；目标、工具回执、结论和缺口落盘。群路由、策略计算、调度和外发授权各自保留。

## v0.13.0 · 阶段 1

入口沿用已绑定的飞书应用机器人本人私聊。发“结合我之前保存的端侧AI研报和最近一次雷达结果，判断有哪些值得继续研究的对象。我主要关心收入兑现。”可创建一次研究。同样支持回复资料卡对照上次疑问、给出 G 编号用新公告核对旧缺口。本人私聊发送“研究记录 G-编号”读取该次成果。多项待选时列出候选。没有给每个用户问题都新增收藏。

- `server/goal-research/route.ts` 在统一路由分流前核验私聊，解析研究目标、已绑定的材料和上次事项；附件收件、普通聊天和群聊保持原入口。文本识别有边界，尚非通用自然语言规划器。带附件可先按原流程收件，再回复其资料卡。
- `loop.ts` 每次由既有模型提出一个 schema 限定的动作，工具结果再次送模型；对结束条件、历史引用、逐字引用和来源版本做程序检查。模型不能指定收件人、凭据、网址、任务开关或价格线。失败时只呈现实际取得的选段和缺口，工具完成与问题解决分开记录。
- `tools.ts` 使用本人已存资料搜索、当前原文及有效批注、历史问题、获准历史检查 R / 指定事件 E 和许可交易所披露搜索。只向披露搜索发送已获准快照返回的公司名和固定公开指标。返回来源、时间、覆盖说明、状态和错误码；入库日期不充当披露日。阶段 1 未开放实时行情工具或第二套正式收盘源。
- `store.ts` 用 SQLite 属性和外键将 G 号、所有者会话、原问题、调用次数、动作参数、工具回执、简报及下一条件连在一起。已有原件和快照继续在原模块维护。来源版本变更会使依赖成果失效，发送前再检查受众与市场来源权限。每次研究留一份独立成果，继续旧问题时保留来源依赖。尚无主动订阅。
- 只读动作先登记、返回后写回。独占 worker 重启后仅重新排队已登记的只读研究；已完成动作留用，结果未知标中断。预算限制默认每次 5 个工具步骤、至多 7 个模型决策，单次另有运行时格式修复；180 秒及 45000 Token 预留上限，现有月预算仍生效。独立服务收费以供应商账单为准。

## 验收记录

同一输入、同一模型、同一真实 11 月 13 日归档的授权范围主题快照；在隔离数据库使用测试私聊身份走真实收件、路由、SQLite 工具、Kimi 和应用决策。第二轮额外加入一份**合成验收研报及批注**。未把个人研报内容或真实账户标识发布到仓库。

| 场景 | 实际顺序 | 结果 |
| --- | --- | --- |
| 库中无研报 | 本人资料未找到 → 读端侧 AI 雷达 → 按两家公司各查一次交易所来源 → 结束 | 两次补查均未取得匹配的可引用片段，模型停在不能按收入兑现排序。计量 7314 Token。 |
| 库中有研报 | 本人资料命中 → 模型选中并读取正文与批注 → 读同一雷达 → 按两家公司各补查一次 → 结束 | 在作者需求预期、历史市场观察和缺少分业务收入之间作区分。计量 12885 Token。 |

两次均为部分完成，公告未命中仅说明这次查询没有取得支持材料。验收没有证明任何证券的收入表现。新增付费实测账本合计 20199 Token；金额未核对。可用 `node --import tsx scripts/live-goal-research.ts --live` 单独复验（会计量），默认 CI 不调用真实模型。工具轨迹保留在忽略目录，本表仅列行为。

隔离回归覆盖同目标分支、普通收藏不增加、跨会话新公告对旧缺口、多个候选、非投资材料、群权限、来源修订及旧消息取消、恶意工具名、虚构引文、工具与 token 上限，以及中断回执恢复。注入测试覆盖越权动作，不等同于所有文本语义均已验证。引用校验仅证明摘录确实存在，模型仍可能过度解读；当前也没有独立的财报语义审计。

## 启停与阶段边界

沿用本机启动文件或构建后 `npm start`。在 .env.local 设 `RESEARCH_ENABLED=0` 并重启可关闭新入口；既有雷达、收件配置和推送通道分别保留。可配置 `RESEARCH_TOOL_BUDGET`（1–8）、`RESEARCH_SECONDS`（1–360）、`RESEARCH_TOKEN_BUDGET`（1–120000）。停服务前等当前执行及外发完成。代码回滚到 v0.12.1 后沿用同一数据目录，旧程序不展示 G 记录。保留数据库备份。

阶段 2 须先验证本人真实私聊续接和撤权，定义事件绑定、变化阈值、外发授权、断点恢复及去重，再考虑新资料或信号唤醒既有事项。阶段 3 需要纠正样本和独立回放通过，由人审核版本，才采纳研究方法修订。

本机工程验收已通过 276 个自动测试、类型检查、生产构建、桌面及移动尺寸 UI 冒烟。真实飞书应用已重新连接，平台已确认接收一条发往绑定所有者的私聊联调邀请。此回执只验证单向投递。本人发题、自动执行及答复送达需要另行核对。
