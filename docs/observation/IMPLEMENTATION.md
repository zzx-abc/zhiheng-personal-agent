# 持续观察与主线机会雷达：v0.7.0 交付说明

这是原知衡项目的增量能力，服务于“用户尚不知道主线，委托系统持续扫描”的任务。当前交付的是**覆盖范围内的行业样本机会扫描**，不是整个 A 股、全部概念主题或行情终端。默认新任务是草稿，不自动启用真实监测或飞书；测试数据不发到真实渠道。

## 复用与新增

| 原有能力 | 实际处理 |
| --- | --- |
| Next.js / React / TypeScript，本机3210端口 | 保留；首页增加持续观察入口和轻量管理面板 |
| SQLite 的 tasks、runs、单任务在途唯一索引 | 复用；`trigger=observation`、`mode=observation`，不新建后端 |
| Node worker、心跳、崩溃恢复 | 复用；增加交易时段调度及确定性处理分支 |
| 腾讯报价、前复权日K解析 | 复用 parseQuote / parseHistory；批量采集及跨任务持久缓存另行补充 |
| 飞书持久 outbox、签名、送达未知与手动重试 | 复用；观察结果按运行版本、期限、有效期检查，测试环境禁止实际发送 |
| 对话、原话、模型、RAG与个人记忆 | 保留；明确观察指令由有边界的任务工具网关执行，其他问题继续原Agent流程；模型可见真实任务摘要 |
| 导出、安全检查与 Git 发布 | 扩展导出观察证据及回执；凭证仍在私密文件中 |

模块：`server/observation/service.ts` 负责生命周期、版本、调度、提交与回放；`types.ts` 定义领域模板及配置；`calendar.ts` 是沪深交易日历；`provider.ts` 获取分类和行情；`detectors.ts` 负责纯计算；`conversation.ts` 是明确意图的自然语言工具入口。UI 与 API 分别是 `app/observation-panel.tsx` 和 `app/api/observation/route.ts`。没有新增多Agent运行层或规则DSL。

## 配置与三种时间

[全范围雷达配置](radar.example.json)和[已知方向配置](direction.example.json)使用**同一套引擎**。后者仅改变观察目标、范围和28天期限，没有复制调度、检测或通知代码；示例不会自动创建实际任务。

- `analysisWeeks: [2,4]`：研究未来2—4周的机会和风险，不是持仓承诺。
- `lookback: {short:3,long:5,volume:20}`：指标回看窗口，不是任务期限。
- `durationDays: null | 28`：首次启用后运行多久。到期日期持久化，恢复、扫描不会延长；修改期限仍锚定首次启用时间。
- `scope`：行业包含/排除、重点方向、每组抽样数量、基准。当前仅支持已接入的10组，未知主题保留为待确认项。
- `rules`：门槛、有效观察次数、联动数、检测器开关、重叠门槛及版本。修改配置产生新版本并重新建立基线。
- `notification`：默认应用内记录；飞书必须由用户选择且连接设置已开启。系统故障提醒与策略提醒分别配置。

“只关注我能理解的行业”不能推断成用户已认可某些产业：保留草稿，需在范围里明确选择。用户关注不等于持仓，检测结果也不写成个人永久事实。

## 数据源与实际覆盖

1. **中证指数官网样本XLS**：10个中证800行业系列指数，000928—000937；000934实际为“800金地”，包含金融地产。按文件中的指数代码、证券代码、交易所、日期验证；保存原始下载缓存、文件日期、接收时间及成员哈希。文件最多接受30天有效日期，每24小时刷新。只有成员/名称映射实际改变才改变哈希，单纯文件日期更新不会每天重建基线。
2. **抽样规则**：每组成员按代码排序等距取样，默认6只，可调3—12只；是确定性抽样，不是权重组合或无偏随机样本。全组成员列表保留以计算Jaccard重叠。行业样本、基准指数分别标识，不混排股票、ETF和行业。
3. **腾讯网页行情接口**：复用现有报价、65条前复权日K解析。股票与沪深300统一到相同历史交易日比较。报价每批最多30个，报价缓存30秒，历史缓存6小时，跨任务复用，未命中缓存时全局最多每秒2次请求；失败不把旧缓存冒充新数据。数据原始时间、接收时间、历史接收时间、单位和价格口径保存在不可变采集帧。
4. **日历**：2026年沪深交易所官方休市表，统一 Asia/Shanghai；周末补班仍不开市。自动检查仅交易时段；2027年等尚未提供日历的年份关闭策略检查并显示原因，不猜测交易日。

真实只读验证（2026-11-13午间）：10/10份官方名单可读取，默认61个对象中59个取得报价和有效日K；两只样本日K缺失/口径校验失败。休市阶段没有形成有效策略确认或通知。随后13:04盘中复测，腾讯日K接口对61个对象均返回HTTP 501，本轮0/61具备可计算历史，正确记录为数据核验失败。已增加全局采集节流与HTTP诊断，但尚未证明节流能解决该故障；不能把故障归因为已确认的限流。这证明实际采集与降级路径，不证明全天可用性或信号有效性。没有购买数据、没有增加Kimi额度，也未发出实际飞书测试。

**当前停用的确认维度**：腾讯接口没有可靠的最终收盘/最终成交量标志，也没有本项目已核实的日K成交量单位约定。因此真实接入只生成盘中初步观察，不升级为正式收盘或跨日收盘确认；量能确认默认停用，开启“必须量能确认”将阻止候选升级。计算器具备正式标志和一致单位下的收盘/20日量比路径，已用隔离数据验证，但没有宣称真实源支持。

不覆盖：北交所、全市场小盘股、全部概念主题、ETF份额与申赎、成交额占比、资金身份/流入、产业链上下游映射和常规公告事件扫描。没有这些数据就不输出相关因果解释。公开下载不代表商业再分发授权；当前沿用个人试用网页接口，不承诺实时性、SLA或长期稳定。

## 指标和事件算法

- 每只股票的N日累计收益：`(前一完整日qfq收盘 / 第N个此前交易日qfq收盘) × (本次报价 / 供应商昨收) - 1`。样本等权平均收益减去基准同区间收益，单位是百分点；不将日涨跌幅相加，不将样本收益称为行业指数收益。
- 逐一核验报价日期、时差、未来时间、开盘/成交状态、价格单位和复权口径。样本与基准报价相差超过5分钟或旧快照超过10分钟，不能确认。
- 历史持续性：最近两个完整历史窗口的3日相对强度大于零；实时持续性另外按不同有效采样时点计数。至少相隔30分钟（或配置的更长频率），同一个快照不会增加次数。
- 广度以全部请求样本为分母，不把未取得的成员从分母静默移除。最低覆盖门槛用于展示；只有完整抽样组参与状态升级、风险判断与比较，避免少了弱样本而虚假增强。
- 联动要求至少两只样本达到相对强度门槛。扩散要求较事件基线至少新增两只上涨样本且广度提升；仅证明样本内扩散，不自动推断整个产业链。
- 五个检测器：新候选、增强、扩散、轮动候选、弱化风险。轮动比较历史领先方向的相对表现差，排除高度重叠对象；不能解释为资金真实迁移。
- 进入候选时固定事件基线，持续满足不重报。每个事件周期按检测器与确认层级去重；风险不受统一冷却时间阻挡，弱化后重新满足条件进入新周期。
- 正式收盘与连续交易日确认必须具有对应的源标志，且是不同、连续交易日；两个小时检查不能算两天。当前真实适配器不提供这些标志，绝不补造。
- 如获得可靠日量，收盘量比使用当日最终量/此前20个完整交易日均量。盘中没有历史同时段数据就不计算量比；不把成交量或成交额当作资金净流入。

首次启动、配置/分类变化、暂停恢复或较长交易时段离线后重建基线，不外发已有强势。重叠信号保留双方证据并关联说明，只发一条主要提醒；同轮消息合并，风险优先。没有综合评分或上涨概率。

## 持久化与迁移

启动时创建增量表，不替换数据库，不清空个人历史：

- `observation_templates`：模板版本快照。
- `observation_tasks`：既有任务的运行扩展（版本、期限、排期、健康）。
- `observation_configs`：不可变配置版本及原话来源。
- `observation_cache`：共享的有限来源采集缓存，不导出缓存副本。
- `observation_frames`：当时的分类、样本、报价、历史及质量证据。
- `observation_checks`：复用runs的检查扩展，每次检查都有结果，包括正常无信号、失败和休市跳过。
- `observation_candidates`：当前候选状态，按task隔离。
- `observation_signals`：不可变事件与去重键（任务、配置、周期、分类、对象、类型、确认阶段）。
- `observation_actions`：启用、配置变更、基线与恢复等审计记录。

通知沿用 `notification_outbox`，每次执行最多一条合并消息，超过有效期或任务版本变化就取消。服务接收、失败和未知分别显示；未知不自动重复发送。关闭网页后由worker继续执行；Mac睡眠或进程关闭仍不能运行。

## 使用与工具入口

启动方式不变：`npm ci`、`npm run build`、`npm start`，或项目的启动脚本。无需新增API Key。新增依赖安装从SheetJS官方CDN读取，网络需能访问中证与腾讯。

首页 → **持续观察** → 新建草稿 → 调整范围/期限 → 启用。也可在原输入框发送：

- “请创建A股主线机会雷达，持续帮我观察A股未来2—4周可能形成的主线机会，有新变化再提醒。”
- 在该对话接着说：“启用观察任务”“暂停观察任务”“恢复观察任务”“结束观察任务”。
- “调整观察任务，排除金融，每30分钟检查。”
- “把信息技术加入重点观察。”（明确给出方向；不会猜测‘这个’指谁。）
- “现在检查一次观察任务”“雷达今天运行得怎么样？”
- “为什么能源方向进入雷达候选？”“这个观察任务过去四周表现如何？”

自然语言入口是有限、可验证的明确意图网关，不是声称任意复杂语言都能可靠执行。歧义、多任务未指定对象、未知主题或未知个人理解范围时会保留草稿/要求明确对象；完整配置始终可在界面调整。普通市场讨论、转发文章不创建监控。外部材料不能修改任务或扩大权限。

`/api/observation` 同源本机API提供 create/configure/status/check/replay；GET提供任务、历史和指定证据帧。对话操作复用同一组服务函数。模型看到的是当前运行事实，不是把短期市场状态写成永久用户记忆。扫描、状态与通知均不依赖模型。

## 复盘与验证边界

历史回放只使用系统当时保存的帧及配置，拒绝未来成分版本，不抓取最新数据补过去。原始信号单独保留；区间重算从第一帧重新建立基线，与此前状态下的原信号并列显示，不覆盖旧记录。最多返回200帧；当前只提供最近四周快捷入口，底层API可指定起止时间。不计算可实现收益或策略收益率。

测试用例覆盖日历、错日/旧数据、缺失与口径、盘中回落、单股孤立上涨、广度/联动、量能停用、基线与重复、阶段、重叠、风险与恢复、配置隔离、到期、并发排队、执行中暂停/修改、跨进程持久化、回放未来信息和自然语言授权；通知超时/失败/重试沿用现有测试。浏览器检查覆盖现有对话建草稿、启用/检查/暂停/配置/恢复/结束、导出、回放与窄屏。

发布前实际验证：155项程序测试（其中23项观察测试）、类型检查、生产构建和浏览器流程通过。本机运行版本已更新，首页与观察API经只读检查；用户任务仍为空，外部通知保持原设置。

运行 `npm run radar:check -- --live` 可做独立临时数据库中的只读真实采集，明确不调用模型、不发送通知；完整输出只留在忽略的artifacts目录。构建与自动测试不调用该真实采集脚本。

仍待验证/后续：真实盘中持续多日的信号质量和提醒及时性、飞书实际收件链路、正式收盘/量能数据源、历史成分点时数据、完整主题和ETF覆盖、一般化的任意自然语言工具调用、专用长期历史统计视图。没有这些证据，不宣称是全市场扫描、稳定投资策略或完整自主研究系统。
